# OpenLAN 开发文档

面向二次开发者的实现说明：架构、模块、HTTP/SSE 协议、P2P 状态机、安全模型与测试。

## 1. 架构总览

OpenLAN 是一个**零框架 Node.js 应用**：`server/` 提供 HTTP 服务与全部业务逻辑，`public/` 是纯原生 JS 单页应用（SPA）。浏览器与会话之间使用 **SSE** 实时推送，文件下载使用 **HTTP Range 分片并发**；两个 OpenLAN 实例之间使用自研 HTTP **P2P 状态机**直传（UDP 组播只负责发现，不传输数据）。

```text
┌──────────── 浏览器 A（本机页面）───────────┐     ┌──────── 浏览器 B（同一主机）────────┐
│ public/ SPA（OLU/OLA/OLUI/OLE 四模块）      │     │  同样打开 http://host:5555          │
└──────────────┬───────────────────────────┘     └────────────────┬──────────────────┘
               │ fetch + SSE(/api/events)                          │ offer 会话推送（同实例内）
               ▼                                                    ▼
┌─────────────────────────── server/state.js（内存状态中枢 + EventEmitter）────────────┐
│ instance 身份(OL-*) · sessions · peers · shares · offers · inbound/outbound · records │
└───────┬──────────────────────────┬────────────────────────────────────────────────────┘
        │ discovery.js             │ http.js 路由
        ▼ UDP 组播 239.76.66.66    ▼ HTTP API + Range + SSE + 静态
  发现其它 OpenLAN 实例 ────────▶ p2p.js（invite/go/chunk/complete 状态机）
        └──── 跨实例点对点数据直传（另一台 OpenLAN 的 :5555）────────────────────────┘
```

## 2. 运行模型

- **实例（instance）**：每个 OpenLAN 进程一个，身份 `OL-<10位>` 与签名密钥存于 `identity.json`（`--data-dir`）。实例名默认 `主机名 的 OpenLAN`。
- **会话（session）**：一个浏览器标签页一个，客户端生成指纹 `sid`（`s-` + 62 位字符表随机串，localStorage 持久化）并随请求以 `x-sid` 头发送；心跳 `/api/session/heartbeat` 每 20 秒刷新在线状态，SSE 断开视为离线。
- **对端（peer）**：发现/登记到的其它实例。组播发现在线 TTL 60 秒；手动登记（`POST /api/peers`）TTL 6 小时。
- 会话推送、实例直传均落盘到**接收目录**（`downloads/`），P2P 文件按 `发送者名_YYYYMMDD-HHmm_<pid>/` 分文件夹保存。

## 3. HTTP API

公共约定：JSON；登录态通过请求头 `x-sid`；设了 PIN 时除白名单外一律 `401 {pinRequired:true}`。跨实例专用端点放 `_routeP2P`，走 `x-openlan-pin` 头校验（两实例 PIN 需一致）。

### 3.1 公开端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/bootstrap` | 实例信息（名称/版本/目录/端口/`lan` 地址列表/`features`）；`lan` 按「真实网卡优先、虚拟网卡次之」排序，供前端生成二维码与分享链接 |
| POST | `/api/session/open` | 开会话（`{sid,name,pin?}`），返回名称；PIN 错误时 401 |
| GET | `/api/events?sid=` | SSE 长连接（见 §4） |
| GET | `/api/qr?text=` | 生成二维码 PNG |

### 3.2 会话 / 设备

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/session/heartbeat?sid=` | 心跳 |
| POST | `/api/session/name` | 修改会话显示名 |
| GET | `/api/sessions` | 列出网页会话 |
| GET | `/api/peers` | 列出 OpenLAN 实例对端 |
| POST | `/api/peers` | 手动添加 `{ip, port, name?}`，返回 peer（含 `id`） |
| GET | `/api/devices` | 合并排序后的全部设备（session + peer） |

### 3.3 共享文件

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/files` | 文件列表，每项含 `{token,name,size,mtime}` |
| POST | `/api/upload` | 原生流式上传，头 `x-name`(URI 编码)、`x-size`、`x-sha256`；同名自动重名 `xx (1).ext`；长度/SHA 不符自动丢弃 |
| DELETE | `/api/files/:token` | 删除共享文件 |
| GET | `/api/down/:token` | Range 分片下载（206/200/416），见 §7 |

### 3.4 快速分享（二维码 / 提取码）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/shares` | `{files:[token], text?, minutes?}` 创建 share，返回 `{code(8位), link, expireAt, files}` |
| GET | `/api/shares/:code` | 查询分享详情（过期返回 404） |
| GET | `/s/:code` | 302 → `/?share=CODE`（扫码/短链跳转领取页） |

### 3.5 会话推送（offer）与实例直传遥控

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/offers` | `{targets:[{kind:'session'|'peer', id}], files:[token], text?}`；session 走 offer，peer 走 P2P invite；返回 `{sessionOffers,outbounds,error?}` |
| GET | `/api/offers/:oid` | 查询 offer |
| POST | `/api/offers/:oid/accept` | 接受 → 客户端开始下载，完成后 |
| POST | `/api/offers/:oid/done` | `{detail?}` 标记完成 |
| POST | `/api/offers/:oid/reject` | 拒绝 |
| GET | `/api/inbox` / `/api/outbox` | 收 / 发箱（inbound / outbound 视图） |
| POST | `/api/inbound/:pid/accept` | 接受实例直传（回调 P2P `go`） |
| POST | `/api/inbound/:pid/deny` | 拒绝实例直传 |
| GET | `/api/records` | 运行内存记录（接收/发送/分享/设备接入） |

### 3.6 跨实例 P2P（`/api/p2p/*`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/p2p/invite` | 远端邀请：`{pid:'TX-*', sender:{id,name,host,urls}, files:[{name,size}], text}` → `{ok, baseUrls}`；`autoAccept` 时直接在请求内回调 `go` 并进入接收状态 |
| POST | `/api/p2p/:pid/go` | `{receiver:{id,name,urls}}` 接收端同意，发送端后台开始推块（幂等） |
| POST | `/api/p2p/:pid/denied` | 接收端拒绝 |
| POST | `/api/p2p/in/:pid/chunk` | 推送一个分块（见 §6） |
| POST | `/api/p2p/in/:pid/complete` | 收齐所有文件分块后做最终一致性校验并落定 |
| POST | `/api/p2p/in/:pid/abort` | 任一方中止 |

### 3.7 静态与 SPA

`/css/*`、`/js/*` 直接映射 `public/`；根级静态资源（如 `/OpenLAN-Logo.png`，经 `^/[A-Za-z0-9._-]+\.[a-z0-9]{1,6}$` 识别）同样直出，`/favicon.ico` 与 `/favicon.svg` 路由均映射到 `/OpenLAN-Logo.png`。其余非 API 路径一律回退 `index.html`（单页路由）。旧前缀 `/static/*` 亦受支持。

## 4. SSE 事件

`GET /api/events?sid=`：连接成功后先补发 `hello`（会话回放数据），再推送实时事件：

```text
{ type:'offer',    offer:{oid, from, files, text, state, createdAt}, toSid }
{ type:'inbound',  job:{pid, sender, files, text, state, receivedBytes, totalBytes,...} }
{ type:'outbound', job:{pid, peer, files, text, state, sentBytes, totalBytes,...} }
{ type:'record',   record:{...} }
```

`toSid` 用于多标签页场景路由（offer 只发给目标会话，但同实例广播可让任意标签页做遥控台）。事件分发以类型 + 状态变化去重后刷新对应 UI（`app.js#handleEvent`）。

## 5. 令牌与安全

- **文件令牌**：`hmac(实例secret, 'file|' + name:size:mtime)` 截断 24 位；文件被改名/替换后令牌即失效，杜绝目录遍历与枚举。
- **上传校验**：声明长度超限即断流；收齐后先验长度再验 SHA-256，不符自动删除。
- **实例身份**：`uid(32)` 随机 secret 持久化到 `identity.json`；服务重启令牌不变（因为 secret 不变）。
- **PIN**：页面 PIN 通过 `session/open` 校验后放行；实例间互信通过请求头 `x-openlan-pin` 比对（两者必须配置一致，否则 P2P 返回 403）。
- 响应一律 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`；资源 `no-cache`。

## 6. P2P 分块协议

发送端（调用方）先把共享文件读入内存分块（默认 1 MB × 4 并发，可用 `--p2p-chunk-kb` / `--p2p-threads` 调整）。每个分块 POST：

```http
POST /api/p2p/in/:pid/chunk
x-pid:     传输任务 pid（TX-*）
x-file:    文件序号（从 0 开始）
x-index:   该文件的块序号
x-offset:  该块在文件内的字节偏移
x-length:  块字节长度
x-sha256:  块级 SHA-256（服务端实时校验）
body:      原始二进制
```

接收端维护：

- `_fds[fileIndex]` 已打开文件描述符与 `_targets` 目标路径；
- `_chunkSeen` 集合按 `fileIndex:index` 去重（网络重试只算一次）；
- 写盘后累加 `receivedBytes`，**文件打开互斥队列**（`_ensureQueue`）避免并发 `'w'` 截断竞态；
- 最后一个分块到达后发送端 POST `complete`，接收端校验 `receivedBytes === totalBytes` 与各块 SHA 均通过后置 `done`，任意失败置 `error` 并 `abort`。

状态机：

```text
发送端 outbound: waiting → sending → done
                            ↓(拒绝) denied     ↓(超时/取消) canceled
接收端 inbound:  pending  → receiving → done
                 pending → denied
```

发送端超时（默认 180 s，`--wait-accept`）自动 `canceled` 并通知远端 `abort`。浏览器端下载引擎（`engine.js`）采用同构思路：Range 切分 + 并发拉取 + 按序合并落盘，但仅用共享目录侧的 `Range`（服务端无需为浏览器保留状态）。

## 7. Range 下载实现要点（`http.js#_handleDownload`）

- 解析 `bytes=a-b` / `bytes=-n` / `bytes=a-` 三种形式；
- 越界返回 `416 + Content-Range: bytes */total`；
- 正常命中返回 `206` 与精确 `Content-Length`，用 `createReadStream(abs,{start,end})` 流式输出；
- 文件头固定 `Accept-Ranges: bytes`、`Content-Disposition`（ASCII 兜底 + `filename*=UTF-8''`），方便下载工具识别中文名。

## 8. 前端架构

```text
public/js/
├ util.js   OLU   通用工具 + 会话指纹 sid（唯一写 localStorage 的地方，另存 engine 设置）
├ api.js    OLA   单一 fetch 封装（统一 x-sid、401→lock 事件）+ EventSource 自动重连 + 心跳
├ engine.js OLE   下载任务：size 切分 → fetch(Range) 并发 → 内存合并 → saveBlob
│                 上传：纯 JS 增量 SHA-256（兼容 http:// 局域网无 crypto.subtle）→ XHR
├ ui.js     OLUI  toast/modal/二维码弹层/设备多选器（返回 {el,getChecked,onChange}）
└ app.js    主控  S 单例状态 + 四个标签渲染 + 事件分发 + offer 自动接收 + 进度坞；
                 文件管理：搜索过滤 / 全选 / 批量发送·下载·分享·删除 / 切回前台自动刷新；
                 维护 `lanUrls` 并优先用局域网 IP 生成二维码/分享链接
```

### 局域网地址与二维码

- 服务端默认监听 `0.0.0.0:5555`（`config.js` 中 `--bind` 可改），`util.lanIPv4s()` 枚举所有非回环 IPv4，真实网卡排在虚拟网卡之前。
- `/api/bootstrap` 返回 `lan` 数组；`app.js` 的 `bestOrigin()` 优先使用当前访问地址（若它本身就是局域网地址），否则回退到 `lan[0]`，避免用户用 `localhost` 打开时生成无效二维码。
- `OLUI.qrModal` 支持传入地址数组，多个局域网 IP 时提供下拉选择，方便用户切换至手机可访问的地址。
- 静态根资源经扩展名白名单路由（`/OpenLAN-Logo.png` 等）；`favicon.ico/svg` 映射同一 PNG。

### 主题（多模式切换）

- 取值：`pink`(默认) / `auto` / `light` / `black`；`localStorage['ol_theme']` 持久化，`<html data-theme>` 只落**有效主题**：`dark | light | black`（pink→dark；auto→跟随 `prefers-color-scheme`）。
- 三套 CSS 变量：`:root`(暗色粉色默认)、`html[data-theme="light"]`、`html[data-theme="black"]`；颜色、透明玻璃、阴影与表单控件统一走 `--*` 变量，因此切主题零 JS 重排。
- `app.js#applyTheme()` 负责写变量/同步 `meta[name=theme-color]`，并监听系统深浅色变化；`index.html` 头部有内联脚本先读 localStorage 预置主题防闪屏。
- 顶部「主题」按钮循环四档（`app.js#cycleTheme`），「设置」弹层内另提供分段选择器 `#themeSeg`。

### 移动端与响应式

- CSS 底部含 `@media (max-width:700px / 460px)`：顶栏按钮图标化、标签可横滑、文件行隐藏次要列、弹层近全宽、`qr-img` 自适应、设置行纵向堆叠、输入框强制 16px（防 iOS 聚焦缩放）、toast/传输坞贴边。
- 图标/设备网格使用 `auto-fill`/`repeat` 自适应列宽；本机 `viewport-fit=cover`。

- **模块边界**：`app.js` 只消费 `OLA/OLUI/OLE/OLU` 公开 API，不直接 fetch。
- **offer 分组**：接受会话推送时，把每个文件的下载任务打上 `group=oid`，`bindEngine` 在组内全部任务终态后统一 `POST /api/offers/:oid/done` 通知发送方。
- **状态双端一致**：UI 维护 `offerMap/inbound/outbound` 三张表，SSE 只做增量 `set`，渲染层按需重绘；传输坞每 120 ms 节流刷新。
- **无构建**：纯浏览器 `<script>` 顺序加载，IE 不支持；请使用现代 Chromium/Safari/Firefox。

## 10. 开发约定

- Node 18+，仅运行时依赖 `qrcode`（控制台与 `/api/qr` 用）。
- 服务端默认监听 `0.0.0.0`，部署时需在系统防火墙放行 Node.js 及对应 TCP 端口，否则外部设备无法访问。
- `cfg.open` 默认 `true`（自动打开浏览器），可用 `--no-open` 关闭；自动化测试均显式传 `--no-open`。
- 目录展示一律用 `util.displayPath()`：位于 `process.cwd()` 内显示 `.\xxx` 相对形式，否则原样显示绝对路径。
- 服务端每个模块导出 `class`，构造时注入 `state`/`cfg`，便于单测与装配；`state.js` 作为 EventEmitter 广播 `push` 事件。
- 文件写入一律 `fsp` + `createWriteStream`，分块上传勿整读超大文件。
- 文件名/文本进入日志、落盘、URL 前调用 `safeBaseName` / `encodeURIComponent`；任何用户可写路径都必须拼接后校验 `startsWith` 前缀（见 `_serveStatic`）。
- 确认类弹窗统一走 `OLUI.confirmModal`：内部用 `settled` 守卫保证**用户首次选择优先**（务必先 `resolve` 再 `close()`，`close()` 触发的 `onClose` 只会回退兜底 false）。接收箱按钮统一挂在 `#inboxList` 的**事件委托**（`inboxAction`），新增按钮无需逐卡绑定。
- 提交前至少通过第 9 节全部命令。
